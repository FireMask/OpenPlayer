# SPEC 23 — Button board PCB (side strip) Rev A

> **Status:** Implemented
> **Depends on:** SPEC 22 (carrier PCB, J4 pinout, generator scripts), SPEC 20 (POWER/PLAY gestures)
> **Date:** 2026-10-26
> **Objective:** Design a long, narrow button strip PCB with seven 6×6 mm tactile switches in a row and an 8-pin JST-XH matching the carrier's J4, generated by scripts shared with the carrier.

## Scope

**In:**

- **Shared generator code** in `hardware/common/`:
  - `pcbgen.py`: symbol loading + schematic writer, outline/text/hole helpers, the grid router, GND pour and stitching. Moved out of `hardware/pcb/scripts/build_sch.py` and `build_pcb.py`.
  - `export-fab.ps1 -Board <dir>`: ERC + DRC gate, Gerbers/drill zip, BOM, renders. Replaces `hardware/pcb/scripts/export-fab.ps1`.
- **Carrier refactor:** `hardware/pcb/scripts/` now uses `common/`. Same parts, nets, placement and rules; it must still regenerate ERC/DRC/parity-clean. No change to the board's design.
- **Button board** in `hardware/buttons/`:
  - `openplayer-buttons.kicad_pro/.kicad_sch/.kicad_pcb`, generated by `scripts/netlist.py`, `scripts/build_sch.py`, `scripts/build_pcb.py`.
  - **SW1–SW7:** 6×6 mm THT tactile switches on the front (facing the side wall). Top to bottom: POWER, VOL+, VOL−, PREV, PLAY, NEXT, MENU, with an extra gap between groups (power | volume | playback).
  - **J1:** `CARRIER`, JST-XH 8-pin on the back at the top end, lying along the strip. Same pinout as the carrier's J4 (1 GND, 2 PLAY, 3 PREV, 4 NEXT, 5 VOL+, 6 VOL−, 7 MENU, 8 KEY), so the cable is straight pin 1 → pin 1.
  - **H1–H2:** M2 mounting holes, one at each end.
  - **Parameters:** `BTN_PITCH` (10 mm), `GROUP_GAP` (4 mm), `BOARD_W` (14 mm). The board length follows from them.
  - **Silkscreen:** board name + "Rev A", each button's name, J1 pin labels, pin 1 marker.
  - `netlist.py` self-check: the J1 pinout must match `J4` in `hardware/pcb/scripts/netlist.py`.
  - ERC and DRC (with parity) clean; fabrication output in `hardware/buttons/fabrication/`.
  - `hardware/buttons/README.md`: regenerate, resize, pinout, cable (XH-8 to XH-8, straight).
- **Docs:** `docs/pcb-requirements.md` gets a button-board section; `hardware/pcb/README.md` points to the shared export script.

**Out of scope (for future specs):**

- Enclosure and button holders/caps.
- Ordering, assembly and testing of either board.
- LEDs, debounce capacitors, ESD protection.
- Splitting the buttons over two boards.
- Any change to the carrier's design or to GPIO assignments.
- Making the cable (only documented).

## Data model

### Nets (`hardware/buttons/scripts/netlist.py`)

| Net | Connections |
|---|---|
| `GND` | J1.1, SW1.2 … SW7.2 |
| `PWR_KEY` | J1.8 → SW1.1 (POWER) |
| `BTN_VOLUP` | J1.5 → SW2.1 |
| `BTN_VOLDN` | J1.6 → SW3.1 |
| `BTN_PREV` | J1.3 → SW4.1 |
| `BTN_PLAY` | J1.2 → SW5.1 |
| `BTN_NEXT` | J1.4 → SW6.1 |
| `BTN_MENU` | J1.7 → SW7.1 |

Net names are the carrier's, so J1 pin N carries the same net as carrier J4 pin N. The self-check asserts this by importing the carrier's `NETS`.

### Parts

| Ref | Value | Symbol | Footprint |
|---|---|---|---|
| SW1–SW7 | POWER, VOL+, VOL−, PREV, PLAY, NEXT, MENU | `Switch:SW_Push` | `Button_Switch_THT:SW_PUSH_6mm` |
| J1 | CARRIER | `Connector_Generic:Conn_01x08` | `Connector_JST:JST_XH_B8B-XH-A_1x08_P2.50mm_Vertical` |
| H1, H2 | M2 | `Mechanical:MountingHole` | `MountingHole:MountingHole_2.2mm_M2` |

All `SW_PUSH_6mm_H*` variants share the same pads; the actuator height (4.3–13 mm) is picked when buying, once the holders are designed. The BOM says "6×6 THT tactile, height per enclosure".

### `hardware/buttons/scripts/build_pcb.py` parameters

```python
BTN_PITCH = 10.0   # mm, switch center to center within a group
GROUP_GAP = 4.0    # mm, extra space between groups
GROUPS = [["SW1"], ["SW2", "SW3"], ["SW4", "SW5", "SW6", "SW7"]]  # top to bottom
BOARD_W = 14.0     # mm, strip width
END_MARGIN = 5.5   # mm, from the last switch / connector to the board end (holes sit here; the M2 hole courtyard is 5 mm)
```

Board length = connector zone + switches + gaps + margins, computed by the script and printed when it runs.

### `hardware/common/pcbgen.py` (moved, not new)

`load_symbol`, `write_schematic`, `uid`, `outline`, `text`, `Router`, `pour`. Each board's scripts pass their own name, parts, nets, placement and parameters.

## Implementation plan

1. **Shared module.** Create `hardware/common/pcbgen.py` by moving the generic code out of `hardware/pcb/scripts/build_sch.py` and `build_pcb.py` (symbol loading, schematic writer, `uid`, outline/text helpers, `Router`, `pour`). The carrier scripts import it. Check: the carrier regenerates with ERC 0, DRC + parity 0/0/0, the same net table and the same placement.
2. **Shared export.** Move `export-fab.ps1` to `hardware/common/export-fab.ps1 -Board <dir>`, deriving the file names from the board folder. Delete the old script; update `hardware/pcb/README.md`. Check: `-Board pcb` produces the same set of outputs as before.
3. **Button netlist.** `hardware/buttons/scripts/netlist.py` with parts, nets and a `__main__` self-check: every J1 pin's net equals the carrier's J4 pin net, and each switch has one signal pin and one GND pin. Run → `OK`.
4. **Button schematic.** `hardware/buttons/scripts/build_sch.py` writes `openplayer-buttons.kicad_sch` and `.kicad_pro` via `pcbgen`. Check: ERC 0 errors, and the exported netlist matches `NETS`.
5. **Button placement.** `hardware/buttons/scripts/build_pcb.py`: strip outline from the parameters, switches on the front in group order, J1 on the back at the top end, H1/H2 at the ends, silkscreen. Check: DRC shows only "unconnected" items.
6. **Button routing.** Same router: signals on F.Cu, GND pour on B.Cu (plus F.Cu stitching). Check: DRC + parity 0/0/0.
7. **Fabrication and docs.** Run `export-fab.ps1 -Board buttons`; write `hardware/buttons/README.md`; add a button-board section to `docs/pcb-requirements.md`.

## Decisions

- **Yes:** one row of 7 side buttons, Walkman-style. Fits the vertical, iPod-shuffle-like case with the round display on top and battery + charger at the bottom.
- **No:** iPod-style ring around a center button. It doesn't fit the side layout.
- **No:** two separate boards (e.g. playback on the front, volume on the side). One strip, one cable.
- **Yes:** the strip lies flat against the side wall, with vertical 6×6 THT switches pressing through it. They're easy to find, sturdy, and the user's holders guide the caps.
- **No:** right-angle switches on a board parallel to the front face. Specific parts, and that board would compete with the carrier for depth.
- **Yes:** top-to-bottom order POWER | VOL+ VOL− | PREV PLAY NEXT MENU, with larger gaps between groups so buttons can be found by touch.
- **Yes:** the same switch for POWER. Accidental presses are prevented by the case/holders (recessing), not the PCB.
- **Yes:** switch height chosen at purchase. All `SW_PUSH_6mm_H*` footprints share pads, so the PCB doesn't depend on it.
- **Yes:** JST-XH 8 with the same pinout as carrier J4, so the cable is straight pin 1 → pin 1. Net names are reused from the carrier and checked by script.
- **Yes:** connector at the top end, on the back, lying along the strip. It's closest to the carrier, and the cable leaves toward the inside of the case.
- **Yes:** two M2 holes, one at each end, for screwing the strip to the holders.
- **Yes:** pitch, group gap and width as parameters (10 / 4 / 14 mm). No case measurements yet; the user adapts the case to the PCB, or the numbers later.
- **Yes:** shared code in `hardware/common/` (generators, router, export script). Copies drift; the router is the expensive part.
- **No:** debounce capacitors, LEDs, ESD parts. Debounce is already in software (`debounceSeconds`), and the Pi's internal pull-ups are enough.

## Risks

| Risk | Mitigation |
|---|---|
| The refactor changes the carrier by accident. | Step 1 checks ERC/DRC/parity, the net table and footprint positions against the current board before going on. |
| A 14 mm strip with 6.5 mm switch pads leaves little room for the routing channel. | Signals on F.Cu along one side and GND pour on B.Cu; widen `BOARD_W` if routing fails. |
| The cable gets made crossed (pin 1 → pin 8). | Same pinout and pin 1 marker on both boards; the README says "straight, pin 1 to pin 1"; check continuity before connecting. |
| The switch height doesn't match the holders. | The PCB doesn't depend on height; pick the switch after the holders are designed. |
| POWER goes to the module's `K` pad, where (per seller listings) a double press turns the 5 V output off immediately, without a safe shutdown. | Recess POWER in the case; shut down with a 3 s hold on PLAY (SPEC 20); confirm the module's `K` behavior at bring-up. |
| A press in the pocket bumps a neighboring button. | Group gaps; holders and caps in the case (out of scope). |

## What is **not** in this spec

- Enclosure, button holders and caps.
- Ordering, assembly and testing.
- LEDs, debounce capacitors, ESD protection.
- Two-board button layout.
- Carrier design or GPIO changes.
- Making the cable.

Each one, if it lands, goes in its own spec.
